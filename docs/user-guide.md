# 사용자 안내서

YANGPA를 쓰는 사람을 위한 설명입니다. 무엇을 할 수 있는지와 함께, **무엇을 지켜 주고 무엇은 지켜 주지
못하는지**를 그대로 적습니다(기획서 원칙 "지킬 수 있는 것만 약속").

- 앱의 모든 기능은 명령줄 도구 `yangpa`로도 할 수 있습니다. 아래 예시의 `yangpa …`는 앱에서 같은 메뉴를 찾아도 됩니다.
  `yangpa <명령> --help`로 인자를 볼 수 있습니다.
- 설계 세부는 [protocol.md](protocol.md), 기획서와 달라진 점·기본값은 [decisions.md](decisions.md), 상시 시더는
  [headless.md](headless.md)를 보세요.
- 개발 중인 소프트웨어이고 외부 보안 감사를 받지 않았습니다([SECURITY.md](../SECURITY.md)).

## 1. 구조 한눈에 보기

- **서버가 없습니다.** 내 컴퓨터의 데몬(`yangpad`)이 친구·크루 멤버의 데몬과 직접(또는 다른 멤버 노드를 거쳐)
  주고받습니다. 앱·CLI·AI 연동은 모두 이 데몬의 클라이언트입니다.
- 창을 닫으면 앱은 트레이로 내려가 계속 돌며 메시지·알림을 받습니다. 트레이 아이콘을 누르면 창이 다시 열리고, 아이콘 메뉴의
  "끝내기"로 앱을 끝냅니다. 닫을 때 바로 끝내려면 사용자 설정 → 모양·언어 → "닫으면 트레이로 내리기" 옵션을 끄세요(리눅스는 트레이 없이 늘 닫으면 끝납니다).
- 윈도에서는 로그인하면 앱이 함께 켜집니다(기본 켬). 끄려면 사용자 설정 → 모양·언어 → "윈도 시작 시 자동으로 켜기" 옵션을 끄세요.
  로그인할 때 창 없이 트레이에서만 켜지게 하려면 바로 아래 "시작 시 트레이로만 켜기"를 켜세요(기본 끔).
- 화면 언어는 처음에 OS 언어를 따르고(지원하지 않는 언어면 영어), 사용자 설정 → 모양·언어 → "화면 언어"에서 바꿀 수 있습니다.
  한국어, English, 日本語, 简体中文, 繁體中文, Español, Français, Deutsch, Português (Brasil), Русский, Italiano, Bahasa Indonesia,
  Tiếng Việt, Türkçe, हिन्दी를 지원합니다. 번역은 AI가 하고 AI가 한 번 더 검토했으며, 사람 원어민의 검토는 아직입니다. 받은 메시지·익명 가명·CLI는 번역하지 않습니다.
- 데스크톱 앱은 데몬을 함께 싣고 있다가 필요하면 띄우고, **앱을 끝내면 붙어 있던 데몬도 끕니다.** 그동안은
  시딩(다른 멤버에게 데이터 제공)과 알림도 멈춥니다. 데몬을 앱과 상관없이 계속 돌리려면 앱을 `YANGPA_NO_SPAWN=1`로
  실행하세요. 앱이 강제로 꺼지거나 튕겨도 앱이 띄운 데몬은 앱이 끝난 것을 보고 스스로 끝납니다. 앱이 띄우지 않은
  데몬(CLI로 띄운 것, 예전 판이 남긴 것)은 남아 시딩을 계속하고 연결 상대에게 내 IP도 계속 보일 수 있습니다. 그런
  데몬을 끄려면 `yangpa shutdown`을 씁니다. 데스크톱 묶음에는 CLI가 없으니 릴리스의 `yangpa-cli-<판>-<타깃>` 묶음을
  받거나, OS에서 `yangpad` 프로세스를 끝내세요(Windows 작업 관리자 → 세부 정보의 `yangpad.exe`, macOS 활동 모니터, 리눅스 `pkill -x yangpad`). 다음에
  앱을 열면 다시 띄웁니다. 설치 파일(Windows `-setup.exe`·`.msi`, 리눅스 `.deb`)은 업데이트·제거할 때 그 설치본의
  데몬을 끕니다. 열려 있던 앱은 다시 시작하세요. Windows에서 다른 사용자 계정이 띄운 데몬은 끄지 못하니 그 계정에서
  먼저 앱을 끄고, `.AppImage`는 바꾸기 전에 데몬을 직접 끄세요.
- 오가는 모든 데이터(메시지·파일·음성·화면)는 종단간 암호화되고, 내 디스크의 데이터는 SQLCipher로 암호화됩니다.
  DB 키는 OS 키 저장소(Windows 자격 증명 관리자, macOS 키체인, 리눅스 Secret Service)에 둡니다.

| 용어 | 뜻 |
| --- | --- |
| 노드 | 데몬이 도는 기기 하나 |
| 스페이스 | 친구 둘 사이의 1대1 공간. 채널을 여러 개 만들 수 있음 |
| 크루 | 디스코드 서버에 해당. 역할·권한·초대가 있음 |
| 시더 / 피어 | 내 데이터를 남에게 **주는** 역할 / 남에게서 **받는** 역할. 둘 다 켜는 것이 기본 |

## 2. 처음 시작하기

1. 릴리스에서 내 운영체제의 묶음을 받습니다(macOS는 Apple 실리콘·Intel 공용 `_universal.dmg`, Windows는
   `-setup.exe`/`.msi`, 리눅스는 x86_64(`amd64`)·ARM64(`arm64`·`aarch64`)의 `.deb`/`.AppImage`). 같은 릴리스의
   `SHA256SUMS.txt`로 파일을 확인하세요(`sha256sum -c SHA256SUMS.txt --ignore-missing`).
   - 지금은 코드 서명을 하지 않은 묶음입니다. macOS는 처음 열 때 "시스템 설정 → 개인정보 보호 및 보안"에서 열기를
     허용하고, Windows는 SmartScreen에서 "추가 정보 → 실행"을 고릅니다.
   - 새 판이 나오면 앱 위에 배너가 뜹니다. 사용자 설정 → 정보에서 **업데이트 받기**, 다 받으면 **업데이트 설치**를 누르세요.
     확인과 받기는 Tor로 하고, 배포자 서명이 맞는 파일만 설치합니다. Windows 설치판·포터블과 리눅스 `.AppImage`는 앱이
     바꾸고 다시 띄우며, `.deb`·`.dmg`는 받은 설치 파일을 열어 줍니다. Android는 릴리스 페이지를 엽니다.
2. 앱을 열면 **새로 시작하기**로 신원(계정)을 만듭니다. CLI는 `yangpa identity create --name 이름`. 앱은 늘 **Tor**로 연결합니다(8장).
   Tor 망 정보를 받는 동안 처음 연결이 조금 걸립니다.
3. **계정은 내 기기에만 있습니다.** 기기를 모두 잃으면 계정을 다시 찾을 방법이 없으니, 쓸 기기를 미리 연결해 두세요. 모두
   잃었다면 새 신원을 만들고, 앱 밖의 연락으로 친구·크루에게 옛 계정을 친구 삭제·차단·강퇴해 달라고 부탁하세요.
4. 새 기기는 쓰던 기기가 그 자리에서 띄운 링크로만 들어옵니다. 쓰던 기기가 켜져 있어야 합니다.
   - 쓰던 기기의 사용자 설정 → 기기 → **새 기기 연결**에서 **QR 띄우기**를 누릅니다(CLI `yangpa device link`). 링크는 10분 동안
     한 기기만 쓸 수 있고, 새로 띄우면 앞서 띄운 링크는 끝납니다.
   - 새 기기의 첫 화면에서 **내 다른 기기와 연결**을 고르고 **QR 찍기**로 찍거나, 쓰던 기기의 **링크 복사**로 받은 링크를 붙여
     넣습니다(CLI `yangpa device join`, 링크는 표준 입력).
   - 두 기기에 같은 6자리 번호가 뜹니다. 쓰던 기기의 **새 기기 연결 요청** 창은 앱 어디서든 뜨고, 번호가 같을 때만 **허용**하세요
     (CLI `yangpa device link-pending`, `link-approve`, `link-reject`). 거절하면 링크도 끝납니다.
   - 다른 기기도 같은 링크를 쓰면 먼저 온 요청만 남고 그 창에 경고가 뜹니다. 링크가 새어 나갔을 수 있으니 내 새 기기가 맞는지
     꼭 확인하세요.
   - 허용하면 새 기기가 계정의 키를 받고 쓰던 기기와 직접 연결해 첫 동기화를 합니다. 끝날 때까지 로딩 화면이 보이고, 오래 걸리면
     **기다리지 않고 열기**로 넘어갈 수 있습니다.
   - 친구·크루 멤버에게는 경고가 가지 않고, 그 사람들이 보는 내 기기 목록에 새 기기가 하나 더 보일 뿐입니다.
   - **내가 연결한 기기가 아니면** 사용자 설정 → 기기나 `yangpa device revoke <기기 ID>`로 폐기하세요. 폐기된 기기는 다음에
     연결하면 스스로 로컬 데이터를 지웁니다. 그 기기는 계정의 키를 받았으니 새 신원을 고려하세요.
   - **기록 비공개 채널(1:1 포함)의 지난 메시지는 새 기기에 오지 않습니다.**
5. **데이터 위치.** Windows 설치판과 포터블 zip은 모든 데이터(대화·키·첨부·설정·웹뷰 저장소)를 기본으로 실행 파일 옆
   `Data` 폴더에 둡니다(설치판은 보통 `%LOCALAPPDATA%\YANGPA\Data`, 포터블은 폴더째 USB 등에 들고 다닐 수 있음). 설치
   폴더에 쓸 수 없는 MSI(Program Files)는 운영체제의 앱 데이터 경로(`%APPDATA%\yangpa\data`)가 기본입니다. 사용자 설정 →
   저장 공간 → **데이터 폴더**에서 지금 쓰는 폴더를 보고 언제든 다른 폴더로 바꿀 수 있습니다. 새 폴더를 고르면 지금 데이터의
   크기와 옮기는 데 걸릴 예상 시간이 나오고, **데이터 옮기기**(지금 폴더에서는 지워짐, 같은 드라이브면 곧바로, 다른 드라이브면
   복사한 뒤 지움)와 **옮기지 않고 새 폴더에서 새로 시작**(새 폴더에 이미 양파 데이터가 있으면 그 데이터 쓰기) 중에서 고르거나
   취소합니다. 끝나면 앱이 다시 시작합니다. 위치는 실행 파일 옆 `data-dir.json`(MSI는 `%APPDATA%\yangpa\data-dir.json`)에 적히고 업데이트해도 그대로입니다. 설치판을
   지워도 `Data` 폴더는 남습니다. 예전 판(데이터가 `%APPDATA%\yangpa\data`)을 쓰다 새 판으로 바꾸면 데이터는 옮기지 않고 그
   위치를 그대로 쓰며, 설정에도 그 위치가 보입니다. 기본 `Data` 폴더로 옮기려면 같은 화면의 **기본 폴더로**를 누르세요.
6. 기기를 잃어버리면 다른 기기에서 그 기기를 폐기합니다(`yangpa device list`, `yangpa device revoke <기기 ID>`). 꺼져 있을 뿐인
   기기는 폐기하지 마세요. 폐기된 기기는 다시 켜지면 데이터를 모두 지우므로 그 기기에만 있는 지난 대화도 사라집니다. 폐기한
   기기는 모든 그룹에서 빠지고 새 키를 받지 못합니다. 이미 그 기기에 있던 기록은 지울 수 없습니다. 폐기한 기기는 사용자 설정 →
   기기의 목록에서 사라집니다(`yangpa device list`에는 폐기됨으로 남습니다).
7. 기기 이름의 기본값은 OS 이름입니다. 사용자 설정 → 기기의 연필 버튼이나 `yangpa device rename <기기 ID> <새 이름>`으로 바꿉니다.

## 3. 연락처와 친구

- **링크로 추가합니다.** 연락처 링크에는 신원 공개키, 토큰, 만료 시각, 접속 정보(네트워크 ID와 onion 주소)만 들어 있고
  **내 IP 주소는 넣지 않습니다.** 링크가 새도 IP는 드러나지 않습니다.
- **링크를 누르면 앱이 열립니다.** 링크는 웹 초대 페이지 주소(`https://dhtpdud.github.io/YANGPA/#…`)라 앱이 없는 사람은
  그 페이지에서 내려받고, 앱이 있으면 '앱에서 열기'로 친구 추가·크루 참가 창이 링크가 채워진 채 뜹니다(참가는 직접 누름).
  `#` 뒤의 링크 내용은 페이지 서버로 가지 않습니다. 앱 안 메시지에 온 링크는 브라우저를 거치지 않고 바로 창을 엽니다.
  포터블 zip·AppImage는 '앱에서 열기'가 안 되니 '링크 복사'로 붙여 넣으세요.
- **링크를 쓰면 바로 대화합니다.** 링크 주인이 수락하지 않아도 둘이 **임시 연락처**가 되고 1대1 스페이스가 생깁니다.
  막 만든 링크라 아직 닿지 않거나 상대가 꺼져 있으면 "대기 중"으로 남고, 상대가 켜지면 자동으로 다시 보냅니다(7일까지).
  한 사람이 받아 둘 수 있는 임시 연락처는 256명까지입니다.
- **만료.** 만료가 있는 링크로 맺은 임시 연락처는 그 링크가 만료될 때 함께 만료됩니다. 링크를 폐기해도 그 링크로 맺은 임시
  연락처가 바로 만료됩니다. 만료된 연락처와의 1대1 스페이스는 더 보내거나 받지 않고 지난 대화만 읽습니다. 같은 사람이 새
  링크를 쓰면 같은 스페이스로 다시 이어집니다.
- **친구로 올리기.** 임시 연락처를 계속 두려면 둘 다 친구 추가를 누릅니다. 한쪽이 누르면 상대에게 친구 요청이 가고, 상대도
  누르거나 수락하면 친구가 됩니다. 친구는 만료되지 않고, 오래 못 만나도 서로를 다시 찾도록 지금 노드 정보를 주고받습니다.

  ```bash
  yangpa friend link create --single-use --expires 24h   # 1회용·24시간. --expires를 빼면 폐기할 때까지 유효
  yangpa friend link list
  yangpa friend link revoke <토큰 ID>                      # 언제든 폐기(그 링크로 맺은 임시 연락처도 만료)
  yangpa friend add 'yangpa://friend/…'                    # 받은 사람: 바로 임시 연락처와 1대1 스페이스
  yangpa friend list                                       # 친구·임시 연락처·만료된 연락처
  yangpa friend propose 상대이름                           # 친구 추가(상대도 누르면 친구)
  yangpa friend requests && yangpa friend accept <요청 ID> # 받은 친구 추가 요청 수락
  ```

- **안전 번호.** 링크를 다른 경로로 받았다면 직접 만나거나 통화로 안전 번호를 비교하고 확인 표시를 하세요. 중간에서
  링크를 바꿔치기하지 않았음을 확인하는 유일한 방법입니다.

  ```bash
  yangpa friend safety-number 친구이름
  yangpa friend verify 친구이름
  ```

- **프로필**(이름·소개·아바타·배너·테마 색·상태)은 서명된 문서로 친구·같은 공간 멤버에게만 갑니다. 크루마다 다른
  별명을 쓸 수 있습니다(`yangpa profile set --name 이름`, `yangpa profile nickname --crew <크루> <별명>`, 별명을 빼면 지움).
- **표시 상태**는 왼쪽 아래 내 카드를 눌러 바꿉니다. 온라인(기본, 이 기기에 10분 넘게 입력이 없으면 저절로 자리 비움),
  자리 비움, 숨기(동기화·대화는 그대로, 다른 사람에게는 오프라인으로 보임), 오프라인(Tor 연결과 동기화를 끊고 이 기기에서만
  씀, 쓴 글은 다시 온라인이 되면 동기화됨)이 있고, 온라인이 아닌 셋은 15분~3일 또는 무기한으로 정합니다. 기기마다 따로
  정합니다. 오프라인으로 들어가거나 나올 때 앱이 잠깐 다시 연결됩니다.
- **마지막 동기화 시각**: 오프라인인 친구·연락처·크루 멤버의 카드와 프로필에 나와 마지막으로 동기화한 때(년월일시분)가
  보입니다. 같은 메뉴의 "마지막 동기화 시각 숨기기"를 켜면 다른 사람 화면에 내 시각이 보이지 않습니다. 숨기·시각 숨기기는
  상대 앱이 지켜 주는 표시라, 이 기능을 모르는 옛 버전 상대에게는 그대로 보일 수 있습니다.
- **뱃지**: 친구 수(5~100명), 내가 소유한 크루의 멤버 수(10~10000명), 시딩한 양(1GB~1PB), 후원(한 번이라도 $3·$14·$50
  이상)을 넘으면 뱃지를 모으고, 한 번 얻은 뱃지는 남습니다. 원년멤버 🧅는 개발자만 줄 수 있습니다. 모은 뱃지는 프로필
  이름 아래에 보이고, 설정 > 프로필 > 뱃지에서 두 개까지 골라 이름 앞이나 뒤에 붙입니다. 원년멤버 말고는 각자 앱이 계산해
  알리는 값입니다. 뱃지와 헷갈리지 않게 이름과 크루 별명에는 이모지를 넣을 수 없습니다.
- 한 기기에서 추가한 **연락처·친구**는 내 다른 기기에도 나타납니다. 그 기기가 꺼져 있었으면 두 기기가 다시 연결될 때 받습니다.
- **친구 메모**는 이 기기와 내 다른 기기에만 저장되고 친구·멤버에게는 가지 않습니다(`yangpa note set 친구 "메모"`).
- **친구 삭제**(`yangpa friend remove 친구`)는 양쪽의 모든 기기에서 그 연락처와 1대1 대화·파일을 지웁니다. 되돌릴 수 없고,
  상대가 끊어도 내 쪽 기록이 함께 지워집니다. 상대 기기가 꺼져 있으면 다음에 연결될 때 지워지며, 앱이나 기기 밖으로 옮긴 사본은
  지울 수 없습니다. 다시 친구가 되면 새 대화로 시작합니다. 만료된 연락처를 지우면 내 기기에서만 지워집니다.

## 4. 스페이스와 채널

- 1대1 스페이스에도 채널을 여러 개 만들 수 있습니다. 채널 종류는 텍스트·음성·포럼입니다.
- 채널 속성:

| 속성 | 값 | 설명 |
| --- | --- | --- |
| 보안 등급 | 일반 / 휘발성 | 일반은 양쪽 디스크에 암호화 저장, 휘발성은 RAM에만(5장) |
| 참여 방식 | 상시 / 입장·퇴장 | 입장·퇴장 방식은 들어가 있는 동안만 대화에 참여 |
| 채팅 수명 | 없음 / 퇴장 시 / N초 | 만료되면 지움. 일반 등급은 메시지별 키를 폐기해 디스크에서도 복구 불가 |
| 과거 기록 공개 | 공개 / 비공개(기본) | 새로 들어온 사람이 들어오기 전 기록을 볼 수 있는지 |
| 링크 미리보기 | 켬 / 끔 | 보내는 쪽이 만들어 함께 암호화. 휘발성 채널은 설정과 상관없이 만들지 않음 |

- **수정·삭제의 한계.** 삭제하면 정상 클라이언트는 그 메시지의 키를 폐기하지만, 이미 받아 간 상대 기기에서 강제로
  지울 수는 없습니다(수정한 메시지도 마찬가지로 이전 판을 이미 받았을 수 있음).
- **링크 미리보기**는 보내는 쪽이 사이트를 조회해 만들므로 받는 사람의 IP는 그 사이트에 드러나지 않습니다. 대신
  보내는 사람의 IP가 드러납니다. 링크를 `<https://…>`처럼 꺾쇠로 감싸면 미리보기를 만들지 않습니다. 유튜브
  플레이어는 누르기 전에는 불러오지 않고, 누르면 그 서버에 내 IP가 보이므로 직접 연결로 띄운 데몬에서만 열립니다(Tor로 돌거나
  연결 방식을 아직 모르면 꺼짐). 플레이어는 유튜브(`youtube-nocookie.com`) 것만 엽니다.
- **첨부**는 메시지당 10개까지이고, 하나의 크기는 기본 무제한입니다. 크루 관리자(채널 관리 권한)는 채널 설정 → **첨부 용량
  한도** 입력란에 채널마다 MiB로 적습니다: 비우면 무제한, **0**이면 첨부 금지, 그 밖에는 1MiB 이상(카테고리 제외). 한도를 넘는
  파일은 보내지 않고, 첨부 금지 채널에서는 첨부 단추가 꺼집니다. 보내는 쪽이 썸네일을 만들어 함께 보내고, 원본은 피어 설정의
  자동 내려받기 한도 안에서 받습니다(7장). 동영상·음성은 데스크톱 앱이 보내기 전에 장면 하나와 재생 길이를 읽어 함께
  보내므로, 받는 사람은 원본을 받기 전에도 썸네일과 길이를 봅니다(앱이 재생할 수 없는 형식은 썸네일 없이 갑니다).
  휘발성 채널의 첨부는 RAM에만 둡니다(5장). 받는 중인 첨부는 진행률 옆에 지금 받기 속도가 나옵니다.
- **수정·삭제 금지.** 크루 관리자(채널 관리 권한)는 채널 설정의 **수정 금지**·**삭제 금지**를 켤 수 있습니다(카테고리 제외).
  수정 금지면 아무도 그 채널의 메시지를 고칠 수 없고(포럼 글 제목·태그는 메시지 관리 권한이 있는 운영진만), 삭제 금지면 글쓴이가
  자기 메시지를 지울 수 없습니다. 운영진의 삭제와 수명(TTL) 만료는 그대로입니다. 채널 설정은 **저장**해도 닫히지 않고, 설정 안에서
  뜨는 확인 창은 설정 창 위에 겹쳐 떠 닫으면 고치던 내용이 그대로 남습니다.
- **붙여넣기.** 복사한 이미지·파일(스크린샷 포함)을 입력창이나 포럼 글쓰기에 붙여넣으면(Ctrl+V) 첨부가 됩니다. 글자가 함께
  복사됐으면 글자만 붙습니다. 이름 없는 스크린샷은 `붙여넣기-날짜-시각.png`처럼 이름이 붙습니다. 붙여넣은 파일은 데몬 메모리에만
  잠깐 두고(임시 파일 없음) 보내거나 빼면 지웁니다. 하나에 256MiB까지이고, 더 큰 파일은 첨부 단추나 끌어 놓기로 올리세요.
- **글 쓰는 중.** 채널에서 누가 글을 쓰고 있으면 입력창 아래에 'A님이 입력 중…'(넷 이상이면 '여러 명이 입력 중…')이 몇 초
  동안 나옵니다. 그 채널을 볼 수 있고 지금 연결된 멤버에게만 가며(P2P 전용 채널은 함께 참여한 기기, 휘발성 채널은 참가자만),
  저장하지 않습니다. 익명 채널에서는 가명으로 나옵니다. 글타래 안에서는 보이지 않습니다.
- **검색.** 위의 검색 칸은 지금 보고 있는 크루·스페이스(홈에서는 모든 곳)의 일반 등급 메시지를 찾습니다(휘발성은 대상이 아님). `from:이름`을 쓰면 그 사람이
  쓴 글만 찾고(크루·스페이스 안에서만, 이름의 띄어쓰기는 `_`, 검색어 없이도 됨) 입력하는 동안 멤버 이름을 제안합니다. 익명 글은 작성자 검색에서 빠집니다.
  결과를 누르면 그 채널을 열어 그 메시지로 가고(포럼은 그 글이 열림) 검색 결과는 그대로 열려 있습니다.
- 받은 첨부는 **저장 공간 한도** 안에서만 남습니다(7장 "받은 첨부의 저장 공간"). 오래 안 본 첨부는 원본이 비워질 수
  있고 썸네일은 남으며, 다시 받을 수 있습니다. 꼭 남길 첨부는 첨부의 **보관**(핀) 단추로 고정하세요.

### 글 꾸미기(마크다운)

채팅 메시지와 포럼 글은 디스코드와 같은 마크다운으로 꾸밀 수 있습니다. HTML은 쓸 수 없습니다(쳐 넣으면 글자 그대로 보임).

| 쓰는 법 | 보이는 모양 |
| --- | --- |
| `**굵게**` · `*기울임*` · `__밑줄__` · `~~취소선~~` | 굵게 · 기울임 · 밑줄 · 취소선 |
| `\|\|스포일러\|\|` | 가려져 있다가 누르면 보임 |
| `` `코드` ``, ```` ``` ```` 로 감싼 줄 | 고정폭 글꼴(안에서는 꾸밈이 먹지 않음) |
| 줄 앞 `> `, `>>> ` | 인용(`>>>`는 그 뒤 전부) |
| 줄 앞 `# `·`## `·`### `, `-# ` | 제목(큰 것부터), 작은 글씨 |
| 줄 앞 `- `·`* `, `1. ` | 목록 |
| `[글자](https://…)`, `<https://…>` | 링크(http·https만, 마우스를 올리면 실제 주소). 글자가 주소이거나 실제 주소와 다른 도메인처럼 보이면(`[www.paypal.com](https://다른곳)`) 가리지 않고 글자 그대로 보임 |
| `\*` | 꾸밈 기호를 글자 그대로 |
| `:::center`·`:::right` 줄과 `:::` 줄 사이 | 가운데·오른쪽 정렬. 글쓰기 칸의 정렬 단추가 고른 줄을 감싸 줍니다(왼쪽 단추는 정렬을 풂) |

`_기울임_`은 단어 경계에서만, 번호 목록은 세 자리 숫자까지만 알아봅니다("2024. 10. 23."은 그냥 글). 짝이 맞지 않는 기호는 글자
그대로 보입니다. 알림과 포럼 목록의 미리보기에는 꾸밈 기호를 뺀 글이 나오고, 스포일러는 `(스포일러)`로 가려집니다. 옛
앱·CLI에는 쓴 그대로 보입니다.

### 포럼

- **글쓰기.** 포럼의 **새 글**을 누르면 포럼 화면이 글쓰기 화면으로 바뀝니다. 제목, 태그(관리자가 만든 채널 태그 중 5개까지), 본문,
  첨부(이미지·영상·파일, 채팅과 같은 한도)를 넣고 **올리기**(Ctrl+Enter)를 누릅니다. 본문이나 첨부 중 하나는 있어야 합니다.
  **취소**는 쓴 것이 있으면 한 번 더 묻고, 올리면 그 글이 바로 열립니다.
- **글 고치기.** 내 글을 열어 머리의 **수정**(또는 본문의 연필)을 누르면 글쓰기 화면과 같은 수정 화면이 열립니다. 제목·태그·
  본문을 고쳐 **저장**하면 글 제목 아래와 목록에 '(수정됨) 일시'가 붙습니다. 첨부는 고칠 수 없습니다(바꾸려면 새 글로).
  수정 금지 채널이면 **수정**이 없습니다.
- **태그.** 그 포럼 채널을 관리할 수 있는 사람(채널 관리 권한)이 채널 설정 → **태그**에서 태그를 만들고 이름을 바꾸거나
  지웁니다(포럼마다 20개까지). 태그는 글자 하나이고 이모지도 그 글자에 바로 쓰면 됩니다(예: `🎮 게임`). 글쓴이는 그 목록에서 고르기만 하고 글쓰기 화면에서 새 태그를 만들 수는 없습니다. 지운 태그는 글에서도 보이지 않습니다.
- **목록.** 위의 막대에서 정렬(업데이트 시간·최초 작성 시간, 내림차순·오름차순), 보기(목록·갤러리), 태그 거르기(여러 개
  고르고 일부 일치·모두 일치)를 고릅니다. 일부 일치는 고른 태그가 하나라도 붙은 글, 모두 일치는 글의 태그가 고른 태그와 꼭 같은
  글입니다. 고정한 글은 늘 먼저 나옵니다. 갤러리는 글의 첫 이미지·영상을 표지로 씁니다.
  정렬·보기·일치 방식은 채널마다 이 기기의 앱 설정에 기억합니다(고른 태그는 기억하지 않음).
- **대문.** 그 채널을 관리할 수 있는 사람(채널 관리 권한)이 글 하나를 대문으로 정하면, 포럼에 들어올 때 그 글 전체가 맨
  위에 보이고 그 아래 목록이 나옵니다(목록에도 '대문' 표시와 함께 남음). 글을 열어 머리의 **대문으로 지정**·**대문 해제**를
  누르거나, 대문 위의 **대문 해제**, 글을 쓸 때 **대문으로 지정**을 켭니다. 포럼마다 하나이고, 대문 글을 지우면 대문이 비어 보입니다. 대문 표시는 모든 멤버의 크루 상태에 남지만 글 ID만
  담깁니다.

### 콘텐츠 뷰어

텍스트 채널 위쪽 막대의 사진 묶음 단추(**콘텐츠 뷰어**)를 누르면, 그 채널의 글·이미지·영상·오디오·파일을 화면 하나에서 하나씩 넘겨 봅니다.
최신 것부터 보이고, 끝에 가까워지면 이전 메시지를 저절로 더 읽습니다.

- 첨부는 하나씩, 첨부가 없는 메시지는 글 하나로 보입니다. 첨부가 달린 메시지의 글은 위쪽 막대에 나옵니다.
  지운 글과 차단한 사람의 글은 나오지 않습니다. 위쪽 막대의 글쓴이 이름을 누르면 뷰어를 닫고 채팅에서 그 메시지로 갑니다.
- 오디오는 파형으로 보입니다. 파형을 누르거나 끌면 그 자리로 옮겨 재생합니다(아주 길거나 큰 오디오는 파형 없이 막대만).
  오디오와 파일 아래에는 채팅의 첨부 카드가 그대로 나와 받기·저장·보관·파일 다시 잇기를 같은 방식으로 씁니다.
  웹뷰가 그릴 수 없는 형식의 이미지·영상·오디오는 파일로 보입니다.
- 아직 받지 않은 이미지·영상은 썸네일과 **원본 받기**만 보입니다. 뷰어는 보거나 넘긴다고 해서 저절로 받지 않습니다(지금 보는 첨부가
  멤버 기기에 드러나지 않게). 사용자 설정 → **동기화**의 자동 받기 크기 이하 첨부는 평소처럼 데몬이 받아 둡니다.
- 위아래 막대는 마우스를 그 가장자리에 올리면 보입니다. 아래 막대의 위치 막대와 썸네일로 바로 옮겨 갈 수 있습니다. 위치 막대 오른쪽의 핀 단추(**미리보기 고정**)를 누르면
  아래 막대가 늘 보이고 콘텐츠는 그 위까지만 차지해, 영상의 재생 막대가 썸네일에 가려지지 않습니다(고정 상태는 기억함).
- 휘발성 채널에서도 쓸 수 있습니다. 첨부는 메모리에서만 그리고, 보던 위치는 어디에도 남기지 않으며, 캡처가 감지되면 뷰어도 가립니다.

| 키 | 동작 |
| --- | --- |
| ↑ / ↓ | 이전 / 다음 (화면보다 큰 이미지는 먼저 스크롤하고, 끝에 닿으면 넘어감. 이전으로 가면 그 이미지의 끝부분부터) |
| ← / → | 영상·오디오 몇 초 뒤로 / 앞으로(기본 5초) |
| Space | 영상·오디오 재생 / 정지 |
| F | 꽉차게 보기 켜기 / 끄기(끄면 이미지 전체가 화면 안에 들어오게) |
| Enter | 전체 화면 켜기 / 끄기(이미지를 두 번 눌러도 됨) |
| Esc | 보기 설정 또는 뷰어 닫기 |

위쪽 ⚙ **보기 설정**(이 기기의 앱 설정에 저장, 모든 채널에 같음):

- **글 / 이미지 / 영상 / 오디오 / 첨부 파일**: 종류별로 켜고 끕니다.
- **사용자**: 고른 사람이 쓴 것만 보입니다(여러 명 가능, 비우면 모두). 이름 칸이 비어 있으면 불러온 글을 쓴 사람이, 이름을 넣으면
  멤버 중 이름이 맞는 사람이 나옵니다. 익명 글은 누가 썼는지 모르므로 빠집니다. 이 필터만은 저장하지 않아 뷰어를 닫으면 풀립니다.
- **포함할 단어 / 제외할 단어**: 쉼표나 줄바꿈으로 나눕니다. 글이나 첨부 파일 이름에서 대소문자 없이 찾고, 둘 다 걸리면 제외가 먼저입니다.
- **정렬 순서**: 최신순(기본) 또는 오래된순. 오래된순은 채널 기록을 처음까지 모두 읽은 뒤 보여 주므로 큰 채널은 처음 열 때 오래 걸립니다.
  보는 중에 바꾸면 보던 항목에 그대로 머뭅니다.
- **꽉차게 보기**(기본 켜짐)와 **채워서 보기**: 기본은 가로가 긴 이미지를 높이에, 세로가 긴 이미지를 폭에 맞춥니다. 높이 맞춤은
  가로형 만화책, 폭 맞춤은 세로형 웹툰에 알맞습니다. 폭에 맞춘 이미지는 위아래로, 높이에 맞춘 이미지는 좌→우로 스크롤합니다.
- **꽉차게 보기 크기**(10~100%, 기본 100), **오른쪽→왼쪽으로 읽기**(높이에 맞춘 이미지를 일본 만화책처럼 우→좌로),
  **↑↓ 스크롤 길이**(20~5000px, 기본 400), **←→ 영상 이동**(1~60초, 기본 5).

### 알림

데스크톱 앱은 사용자 설정 → **알림**에서 OS 알림을 켜고 끕니다.

- **크루 알림**: 모든 메시지(기본, 스레드 답글은 나를 멘션할 때만) / 나를 멘션한 메시지만 / 끄기. 1대1 스페이스는 늘
  알리고 내가 보낸 메시지는 알리지 않습니다.
- **내용 미리보기**를 끄면 보낸 사람만 나오고 본문은 빠집니다. 휘발성 채널은 설정과 상관없이 "새 메시지"만 나옵니다(5장).
- 앱 창을 보고 있어도 알림이 뜹니다. 다만 지금 열어 둔 채널의 메시지는 화면에 보이므로 띄우지 않습니다.
- 알림을 누르면 앱이 앞으로 오고 그 채널이 열립니다. 창이 뒤에 있으면 작업 표시줄 단추도 깜빡입니다.
- 멘션은 입력창에서 `@`를 쳐서 목록에서 고른 사람만 알림을 받습니다(이름을 그냥 쳐 넣은 것은 멘션이 아님).
- **@everyone·@here**: 크루에서 **많이 멘션하기**(`mention_many`) 권한이 있으면 입력창에서 `@`를 칠 때 목록에 나옵니다.
  `@everyone`은 그 채널을 볼 수 있는 모두, `@here`는 그때 접속해 있던 사람(보낸 뒤 5분 안에 받은 기기)에게 멘션으로 칩니다.
  권한 없는 사람이 쳐 넣으면 `@everyone`으로 보이기는 하지만 아무에게도 멘션·알림이 가지 않습니다.
- **크루·채널마다**: 크루(왼쪽 목록이나 사이드바 머리글)나 채널을 오른쪽 클릭하면 **알림 끄기**(15분~24시간, 직접 켤 때까지)와
  **알림 설정**(기본값 따르기·모든 메시지·@멘션만·알림 없음)이 있습니다. 채널 설정이 크루 설정보다, 크루 설정이 위 크루 알림보다
  앞섭니다. 알림을 끈 동안은 멘션만 알리고, 끈 크루·채널은 흐리게 보이며 안 읽음 표시가 없습니다(멘션 수는 보임). 이 기기에만
  적용되고, 휘발성 채널은 채널마다 정할 수 없습니다(크루 설정은 적용).
- 같은 메뉴에서 **읽음으로 표시하기**, 크루·채널 ID 복사, 크루의 **신뢰 스위치**도 할 수 있습니다. 사람(멤버 목록, 메시지의 이름·프사,
  친구·1대1 목록, 통화 참가자)을 오른쪽 클릭하면 프로필 보기, 신뢰 스위치, 사용자 ID 복사가 나옵니다.
- 앱을 끝내면 데몬도 끝나므로 알림도 오지 않습니다(1장). 윈도 알림 센터는 띄운 알림을 디스크에 남길 수 있습니다.

## 5. 휘발성 채널

```bash
yangpa channel create --crew "게임 모임" --type text --name 비밀 --volatile --join-leave --ttl 30s
yangpa channel join --crew "게임 모임" 비밀
yangpa channel leave --crew "게임 모임" 비밀      # 이 기기의 내용·키를 바로 지움
```

### 지켜 주는 것

- **디스크에 쓰지 않습니다.** 메시지·키·참가자·읽음 위치는 RAM에만 있습니다. 데몬 코드에서도 휘발성 데이터는 디스크
  저장 경로와 타입으로 나뉘어 있어 DB·로그·캐시로 갈 수 없습니다. 디스크에 남는 것은 "이 채널의 AI 읽기를 허용함"
  표시(공간·채널 ID)뿐입니다.
- **RAM에서도 암호문입니다.** 복호화 키만 잠긴 메모리(스왑으로 내려가지 않음)에 두고, 지울 때 0으로 덮어씁니다.
- **수명.** 각 기기가 받은 시각부터 N초를 셉니다(기기 시계가 달라도 됨). '퇴장 시'면 쓴 사람이 나갈 때 남은 기기들도
  그 사람의 메시지를 지웁니다.
- **입장·퇴장 방식.** 나가면 내 기기의 그 채널 내용이 바로 지워지고, 들어오고 나갈 때마다 키를 바꿔 나간 기기는 그
  뒤 메시지를 풀 수 없습니다.
- **재시작·크래시**하면 휘발성 내용은 모두 사라집니다.
- **직접 전달만.** 지금 참가 중인 기기에게만 보내고, 다른 노드가 중계하지 않습니다.
- **늦게 들어온 사람**은 과거 기록 공개일 때만, 지금 참가자들의 RAM에 아직 남은 메시지를 받습니다.
- **알림**은 "새 메시지"라는 제목만 띄우고 보낸 사람·내용을 넣지 않습니다.
- 링크 미리보기는 채널 설정과 상관없이 만들지 않습니다.
- **첨부도 RAM에만.** 보내는 데몬이 파일(또는 붙여넣은 이미지·파일)을 메모리에서 읽어 썸네일·정보를 만들고, 첨부마다 새 키로 암호화해 암호문만
  RAM에 둡니다(키는 휘발성 메시지 안에 넣어 채널 키로 다시 암호화). 받는 기기도 지금 참가자에게서 RAM으로만 받고(조각마다
  해시 검증), 디스크 블롭 저장소·DB·임시 파일·로그에 쓰지 않습니다. 첨부는 메시지와 함께 지워집니다(만료·퇴장·채널 삭제·
  재시작). 늦게 들어온 사람도 메시지가 살아 있는 동안 받을 수 있고, 만료된 뒤에는 누구도 내주지 않습니다. 차단한 사람의
  첨부는 받지 않고 그 사람에게 내주지도 않습니다. 동시에 받는 수와 받기 속도 제한은 일반 첨부와 함께 셉니다(Tor로는
  일반 첨부와 합쳐 한 번에 하나, P2P 연결로 받는 첨부는 따로). 곧 사라지는 휘발성 첨부를 먼저 받습니다.
- **첨부 한도.** 크루의 휘발성 채널은 만들 때 첨부 용량 한도가 **10MiB**로 정해집니다(채널의 첨부 용량 한도(4장)에서 바꿈).
  모든 참가자 기기의 RAM에 올라가므로, 10MiB보다 크게(또는 비워서 무제한으로) 두면 입력란 옆에 참가자 RAM 용량을 고려하라는 빨간
  경고가 나옵니다. 노드 전체 RAM 예산은
  1GiB라 하나도 그 안이어야 합니다. 데몬을 `--volatile-attachment-mib`(하나, 기본 무제한)·`--volatile-ram-mib`(전체)(환경 변수
  `YANGPA_VOLATILE_ATTACHMENT_MIB`·`YANGPA_VOLATILE_RAM_MIB`)로 띄워 바꿀 수 있습니다.
  넘으면 보내기는 바로 거절되고, 받는 쪽은 자동으로 받지 않으며 직접 받기(`yangpa blob fetch`)는 오류로 알립니다
  (다른 메시지가 만료돼 RAM이 비면 다시 받을 수 있음). 보낸 사람이 중간에 나가 받다 멈춘 첨부는 기다리는 동안 받은 만큼만
  RAM을 쓰고, 10분 동안 진전이 없으면 받다 만 것을 지웁니다(직접 받으면 처음부터 다시).
- **저장은 경고 뒤 확인.** 앱에서 휘발성 첨부를 저장하면 "저장한 파일은 메시지가 사라져도 남는다"는 경고를 띄우고
  확인해야 저장합니다. CLI는 `yangpa blob save ... --allow-volatile`을 붙여야 하고, `yangpa blob read`로 파일에 쓸 때도
  (`-o 파일`) 같은 인자가 있어야 합니다(표준 출력은 그대로). AI(자동화 토큰)는 `blob.save`로 저장할 수 없습니다. 다만 읽기를 허용한
  채널에서는 내용을 읽을 수 있으므로, 읽은 내용을 어디에 쓸지까지는 막지 못합니다.
- AI(자동화 토큰)는 사람이 채널마다 허용하기 전까지 읽을 수 없습니다(10장).
- 앱의 웹뷰는 디스크 캐시 없이(incognito) 띄우고, 휘발성 이미지는 메모리 안의 `blob:` 주소로만 그리며, 데몬에서 오는
  파일 응답에는 캐시 금지 헤더를 붙입니다. 우클릭 "다른 이름으로 저장"이나 플레이어의 다운로드도
  저장 버튼과 같은 길로 가서(Windows는 그 저장 창에서 고른 곳에, 플레이어 다운로드는 받기 폴더에 씀), 휘발성 첨부는 위 경고를 확인해야 저장됩니다. 링크를 우클릭해 바로 저장하는 것은 Tor를 거치지
  않으므로 막혀 있습니다(링크를 열어 브라우저에서 저장).
- **직접 확인할 수 있습니다.** 휘발성 채널에 고유한 표식 문자열을 보낸 뒤 `yangpa diag leakcheck <표식>`을 실행하면
  데이터 경로 전체(복호화한 DB 포함)와 로그 파일에 그 문자열이 있는지 찾아 위치만 알려 줍니다. 첨부도 봅니다: 표식을
  넣은 파일을 휘발성 채널에 보낸 뒤 실행하면 키를 아는 디스크 첨부를 풀어 훑고, 휘발성 첨부가 디스크 블롭 저장소에
  있는지도 알려 줍니다.

### 지켜 주지 못하는 것(보장 범위 밖 경로)

| 경로 | 위험 | 이 앱이 하는 일 / 내가 할 일 |
| --- | --- | --- |
| OS 알림 | 알림 센터가 미리보기를 디스크에 저장 | 내용 없는 알림만 띄움 |
| 웹뷰 캐시 | 이미지·응답이 웹뷰 디스크 캐시에 남음 | 메모리 전용 렌더링, 캐시 금지 헤더, 디스크 캐시 끔. Windows(WebView2)는 엔진이 사용자 데이터 폴더에 GPU 셰이더 캐시 같은 파일을 쓸 수 있음 |
| 스왑·최대 절전 | RAM 내용이 디스크로 내려감 | 키만 잠그고 내용은 암호문이라 스왑돼도 읽을 수 없음. 다만 첨부를 보내거나 볼 때 잠깐 생기는 평문(썸네일을 만드는 버퍼, 화면에 그린 이미지·영상)은 내려갈 수 있음. **최대 절전(하이버네이트) 파일에는 키도 기록될 수 있으니** 최대 절전을 끄거나 디스크 전체를 암호화하세요 |
| 크래시 덤프 | 메모리가 덤프 파일로 저장 | 헤드리스 패키지(systemd·Docker)는 코어 덤프를 끔. 데스크톱에서는 OS의 크래시 보고·코어 덤프도 꺼 두기를 권함 |
| 클립보드 | 복사한 내용이 OS 클립보드 기록에 남음 | 휘발성 내용은 복사하지 마세요. 앱 밖으로 나간 내용은 지킬 수 없음 |
| 키보드 앱(Android) | 키보드 앱이 입력한 단어를 학습 사전에 저장 | 휘발성 채널을 보는 동안 키보드에 학습하지 말라고 알리고 맞춤법 검사를 끔. 따르는 것은 키보드 앱 몫이라, 따르지 않는 키보드라면 학습을 끄세요 |
| 첨부 저장 | 받은 사람이 첨부를 파일로 저장 | 경고 뒤 확인을 받아야 저장. 저장한 파일은 메시지가 사라져도 남고 앱이 지우지 않음 |
| 화면 캡처 | 상대가 스크린샷·녹화 | Windows·macOS에서 '캡처 제외 창'을 켤 수 있음(리눅스는 지원 안 함). Windows 앱은 휘발성 채널에서 스크린샷·녹화 프로그램을 감지하면 채널 화면을 검게 가리고 금지 안내를 띄움. 휴대폰 카메라 같은 촬영은 막을 수 없음 |
| 개조된 클라이언트 | 상대가 앱을 고쳐 내용을 저장 | 기술적으로 막을 수 없음. **신뢰하는 상대와만 쓰세요** |

그 밖에, 참가자끼리 일부만 연결된 상황에서는 기기마다 참가자 목록이 달라 볼 수 있는 메시지가 갈릴 수 있습니다.

## 6. 크루

### 만들기와 전환

```bash
yangpa crew create "게임 모임"                       # 멤버 1명짜리 크루 + 텍스트 채널 '일반'
yangpa crew convert --crew 친구이름 --name "게임 모임" # 1대1 스페이스를 크루로(상대 동의 필요)
yangpa crew accept-convert --crew 친구이름            # 상대가 동의
```

1대1에서 크루로 바꾸면 채널·이모지·기록은 그대로이고, 기존 채널은 모두 **과거 기록 비공개**가 됩니다. 기존 대화가
새 멤버에게 보이지 않게 하기 위해서이며, 다시 공개하려면 원래 두 사람이 모두 공개로 바꿔야 합니다. 전환 뒤 요청한
사람이 소유자, 동의한 사람이 관리자가 됩니다. 전환한 뒤에도 그 사람과 1대1로 이야기할 수 있습니다: 친구 목록이나 프로필에서
**대화**를 누르면 둘만의 1대1 대화가 새로 생깁니다(크루는 크루대로 남음).

### 역할과 권한

역할은 이름·색·순위·권한을 가집니다. 채널마다 역할별 권한을 덮어쓸 수 있고, 특정 역할만 보는 **비공개 채널**은 그
채널 멤버만으로 따로 암호화 그룹을 운영합니다(권한 없는 멤버는 키가 없어 풀 수 없음).

```bash
yangpa role create --crew "게임 모임" --name 운영진 --perms manage_channels,kick --color '#e67e22'
yangpa member roles --crew "게임 모임" 철수 --roles 운영진
yangpa channel create --crew "게임 모임" --name 운영 --private-roles 운영진
```

권한 이름: `view_channel`, `send_messages`, `read_history`, `add_reactions`, `attach_files`, `embed_links`,
`use_external_emoji`, `connect_voice`, `speak`, `stream`, `create_posts`, `use_crew_stun`, `mention_many`, `manage_messages`, `manage_channels`,
`manage_roles`, `kick`, `ban`, `create_invite`, `manage_emoji`, `manage_voice`, `manage_space`, `administrator`.
`manage_voice`가 있는 시더 노드는 참가하지 않은 큰 통화의 중계(SFU 호스트)를 맡을 수 있습니다. 중계 노드는 소리·화면
내용은 못 보지만 참가자의 IP와 누가 언제 말하는지는 알므로 믿는 노드에만 주세요([headless.md](headless.md) "통화 SFU 호스트").
자기에게 없는 권한은 줄 수 없고, 자기보다 순위가 낮은 역할·멤버만 다룰 수 있습니다. `administrator` 권한이 있는 역할은
순위 숫자와 상관없이 모든 일반 역할보다 위이고, 관리자 역할끼리·일반 역할끼리만 순위 숫자로 비교합니다(그래서 순위 1인
관리자도 순위 50인 운영진 역할을 고치거나 그 역할의 멤버를 추방할 수 있고, 운영진은 관리자를 추방할 수 없음). 앱의 역할
목록에서도 관리자 역할은 늘 위에 있고 일반 역할과 순서를 바꿀 수 없습니다. 크루의 모든 기기가 이 규칙을 아는 새 판이어야
결과가 같습니다. 모든 변경은 서명된 상태 이벤트라
모든 노드가 같은 규칙으로 검사합니다. 동시에 일어난 권한 변경은 (역할 순위, 논리 시계, 해시) 순서로 모두가 같게
정리됩니다.

### 초대

```bash
yangpa invite create --crew "게임 모임" --expires 24h --uses 10 --roles 손님
yangpa invite list --crew "게임 모임"
yangpa invite revoke --crew "게임 모임" <토큰 해시>
yangpa invite join 'yangpa://invite/…'              # 받은 사람
```

- 초대 권한이 있어야 만들 수 있고 언제든 폐기할 수 있습니다. 만료를 주지 않으면 7일 뒤 만료됩니다.
- 링크에는 크루 이름을 넣지 않습니다(링크가 새도 어느 크루인지 드러나지 않게). 가입 때 줄 역할은 링크가 아니라 크루
  상태에 기록되므로 링크를 고쳐 역할을 바꿀 수 없습니다.
- 멤버 추가·제거 같은 암호화 그룹 변경은 크루의 **커밋 확정 기기**(소유자·관리자 기기)가 확정합니다. 그 기기가
  꺼져 있으면 가입이 대기 상태가 됩니다. 소유자는 크루 설정 → 개요 → **확정 기기**에서 소유자·관리자의 다른 기기로
  바꿀 수 있습니다(CLI `yangpa crew committer --crew … --set <기기>`). 늘 켜져 있는 기기, 예를 들어 내 기기로 붙인
  헤드리스 시더나 관리자 역할을 준 시더를 고르면 가입이 기다리지 않습니다. 그냥 상시 시더를 두는 것만으로는 기록을
  제공할 뿐 확정 기기가 되지 않습니다.
- 크루 목록 위의 **"새 멤버·기기를 암호화 그룹에 넣는 중…"**은 이 기기가 확정 기기이고 그룹에 넣거나 뺄 기기가 남았다는
  뜻입니다. 넣으려면 그 기기의 키 꾸러미가 필요해서, 새 멤버·기기가 한 번도 접속하지 않았으면 접속할 때까지 남습니다.
  확정 기기가 아닌 기기에는 "확정 기기가 접속하면 멤버 변경이 반영됩니다"가 나옵니다.

### 추방·탈퇴·소유권

```bash
yangpa member kick --crew "게임 모임" 철수 --reason "규칙 위반"
yangpa crew transfer --crew "게임 모임" --to 영희
yangpa crew leave --crew "게임 모임"                 # 소유자는 먼저 넘겨야 함
```

- **모더레이션의 한계:** 추방된 멤버는 이후 데이터를 받지 못하지만 **이미 받은 데이터는 계속 갖고 있습니다.** 서버가
  없는 구조의 본질적 한계입니다.
- 탈퇴하면 탈퇴가 다른 멤버에게 닿은 것을 확인한 뒤 이 기기의 그 크루 데이터(기록·키·설정)를 지웁니다.
- 소유자는 앱의 크루 메뉴에서 **크루 해산하기**로 크루를 끝낼 수 있습니다(되돌릴 수 없음). 다른 멤버 기기에는 '해산한
  크루'로 남고, 각자 **크루 나가기**로 지웁니다.

### 차단·신고·밴

```bash
yangpa user block 철수                     # 친구 이름이나 사용자 ID. 크루 멤버면 --crew "게임 모임"
yangpa user blocked
yangpa user unblock 철수
yangpa user devices 철수                   # 그 사람의 기기 목록
yangpa user block-device 철수 <기기 ID>     # 그 계정의 기기 하나만 차단(낯선 기기 등)
yangpa user blocked-devices
yangpa user unblock-device <기기 ID>
yangpa message report --crew "게임 모임" -c 일반 <메시지 ID> --reason "도배" --hide
yangpa report list --crew "게임 모임" --status open                 # 운영진
yangpa report resolve --crew "게임 모임" <신고 ID> --action delete-message --note "첫 경고"
yangpa member ban --crew "게임 모임" 철수 --reason "도배" --delete-recent
yangpa member bans --crew "게임 모임"
yangpa member unban --crew "게임 모임" 철수
```

- **차단**은 이 기기에만 있는 설정입니다. 상대에게 알리지 않고, 내 다른 기기와 맞추지 않으며, 함께 있는 크루에서
  나가게 하지도 않습니다. 그 사람의 메시지는 지우지 않고 한 줄로 접어 보이며(눌러서 펼침), 알림·안 읽은 수·친구
  요청·첨부 자동 받기에서 빠지고, 내 노드는 그 사람에게 메시지 기록을 제공하지 않습니다. 다른 시더가 주는 내 메시지까지
  막지는 못합니다.
- **기기 차단**은 그 사람 계정에서 기기 하나만 막습니다(앱: 프로필의 "기기" 목록). 친구 계정에 낯선 기기가 보일 때처럼
  그 기기만 끊고 싶을 때 씁니다. 그 기기와는 연결하지 않고,
  그 기기가 쓴 메시지만 접으며, 그 계정의 다른 기기는 그대로입니다. 이 기기에만 있는 설정이라 그 기기가 이미 받은 대화나
  다른 사람을 통해 받는 것은 막지 못하니, 계정 주인에게 알려 그 기기를 폐기하게 하세요.
- **신고**는 크루 채널의 메시지만 됩니다. 그 채널을 볼 수 있는 운영진(`kick`·`ban`·`manage_messages` 권한)의 기기에만
  봉인해 보내며, 메시지 내용은 싣지 않고 작성자는 받지 않습니다. 다른 멤버는 신고가 있었는지 모릅니다. 운영진 기기가
  꺼져 있으면 30일까지 다시 보냅니다. `--hide`(앱 기본값)면 이 기기의 목록·검색·알림에서 숨기고 시딩에서도 뺍니다.
- **신고 처리**는 닫기(`dismiss`), 메시지 삭제, 작성자 추방·밴 중 하나입니다. 처리 메모는 운영진끼리만 보고, 추방·밴
  사유로 쓰지 않습니다(사유는 모든 멤버가 읽을 수 있는 상태 기록에 남기 때문).
- **밴**(`ban` 권한)은 내보내고 다시 들어오지 못하게 합니다(옛 초대·새 초대 모두). 모든 노드가 같은 규칙으로 거절하도록
  상태 이벤트로 남으므로 **밴 목록과 사유는 프로토콜상 모든 멤버의 노드에 있습니다**(앱은 `ban` 권한자에게만 보여 줌).
  `--delete-recent`는 그 사람이 밴 직전 24시간 동안 쓴 메시지를 각 노드에서 지웁니다(이미 받은 사본은 되돌릴 수 없음).
  밴을 풀어도 다시 들어오려면 새 초대가 필요합니다.

### 그 밖

- 포럼 채널: 게시글마다 제목·본문·태그·첨부, 고정·잠금, 정렬·갤러리·태그 거르기, 대문(4장 "포럼", `yangpa forum …`).
- 커스텀 이모지: 디스코드 표기(`<:이름:ID>`, 움직이면 `<a:이름:ID>`), png·gif·webp, 크기 제한 없음, 1대1에서도 사용.
  크루는 관리자(크루 관리 권한)가 크루 설정 → 이모지에서 최대 개수(500까지)와 이모지 하나의 최대 크기를 정할 수 있습니다.
  이모지마다 올린 사람의 사진·이름이 보입니다. 역할 이름에도 이모지를 넣을 수 있습니다(역할 편집의 이모지 단추).
  다른 공간의 이모지 사용은 공간 설정으로 켜야 합니다.
- 관리 화면의 "시더 커버리지"가 0인 채널은 지금 아무도 기록을 제공하지 않는 채널입니다(7장).

## 7. 시딩: 무엇을 저장·제공·수신할지

시더(남에게 주기)와 피어(남에게서 받기)는 따로 켜고 끕니다. 따라잡기와 파일 스웜에 적용되고, 실시간 전파(그 순간
온라인인 멤버에게 바로 가는 새 메시지)와 상태 동기화(채널·역할·멤버 목록)는 설정과 무관합니다.

| 설정 | 기본값 |
| --- | --- |
| 시더 | 켜짐, 모든 종류, **본인이 연 채널만**, 송신 10MiB/s, 동시에 보내 줄 기기 4대 |
| 피어 | 모든 종류, 수신 10MiB/s, 자동 내려받기 20MiB 이하. 우선순위 텍스트 > 이모지 > 이미지 > 영상 > 파일 > 기록 묶음 |
| Tor(앱은 늘) | 동시에 보내 줄 기기 2대, 자동 내려받기 2MiB(대역폭 설정은 같지만 Tor 회로가 먼저 한계라 파일은 보통 초당 수십~수백 KiB). P2P 전용 채널에서도 이 기본값을 씀. 다만 P2P 전용 채널·서로 신뢰한 사람에게서 받는 파일은 Tor처럼 묶지 않아 받기·올리기 속도 제한(비우면 무제한)과 회선 속도까지 나옴 |
| 휴면 | 14일 동안 열지 않은 크루는 실시간 구독을 끊고 다시 열 때 따라잡음(1대1·상시 시더 공간 제외) |

```bash
yangpa seed show
yangpa seed set --crew "게임 모임" --types text,emoji,image --upload-limit 2MB/s
yangpa seed exclude --crew "게임 모임" -c 일반 <메시지 ID>   # 이 메시지와 첨부는 제공하지 않음
yangpa peer set --auto-download-max 50MB --priorities text=250,image=150
yangpa seed coverage --crew "게임 모임"                     # 채널별 온라인 시더·보관 노드 수
```

- 시더는 자기가 가진 데이터만 줍니다. 받지 않은 데이터는 줄 수도 없습니다.
- 시더는 요청을 받으면 (1) 요청자가 지금 멤버인지 (2) 그 채널을 볼 권한이 있는지 (3) 들어오기 전 기록이라면 과거 기록
  공개인지 (4) 내 제공 범위인지 (5) 대역폭 여유가 있는지를 차례로 보고, 하나라도 아니면 거절합니다.
- 크루 데이터는 크루 멤버끼리만 주고받습니다(공개 DHT·트래커에 올리지 않음). 조각은 암호화된 채로 오갑니다.
- 아무도 제공하지 않는 데이터는 사라집니다. 받지 못한 구간은 "받지 않은 기록"으로 표시되고, 나중에 다른 시더에게서
  채울 수 있습니다. 늘 켜 둘 노드가 필요하면 [headless.md](headless.md)를 보세요.
- 시더가 되면 내 기기가 남의 콘텐츠를 보관·전달합니다. 그래서 기본 범위를 "본인이 연 채널만"으로 두었고, 메시지 단위로
  뺄 수 있습니다.
- **미리 받기**(`yangpa seed set --prefetch on`, 앱은 사용자 설정 → 동기화)를 켜면 열어 보지 않은 채널의 첨부도 받아 두고
  내줍니다. 늘 켜 두는 시더용이며 아래 저장 공간 한도 안에서만 받습니다.

### 전송 속도와 범위별 제한

- 앱 왼쪽 아래(서버 목록 맨 아래) Tor 표시 바로 위에 지금 올리기(↑ 초록)·받기(↓ 빨강) 속도가 나옵니다. 메시지 동기화와 첨부가 모든 연결(Tor,
  직접 연결, 파일 회로)로 오간 양을 최근 3초 평균으로 보여 줍니다. 통화는 들어가지 않습니다.
- 내가 올린(또는 받아서 내주는) 첨부를 누가 받고 있으면 첨부 옆에 그 사람의 프사·이름·속도가 작게 나옵니다. 익명 채널이면
  '익명'으로 나옵니다(5명까지, 그 밖은 '외 N명').
- 전체 올리기·받기 제한(위 표) 말고도 **크루, 채널, 사람마다** 올리기·받기 제한을 따로 걸 수 있습니다. 이 기기만의 설정이고,
  여러 제한이 함께 걸리면 가장 낮은 값을 따릅니다. 올리기 제한은 그 크루·채널·사람의 요청에 답할 때, 받기 제한은 그 크루·채널의
  첨부나 그 사람이 주는 조각을 받을 때 걸립니다. 크루에서 나가면 그 크루와 채널의 제한은 지워집니다.
  앱: 크루 이름 메뉴의 **이 크루 속도 제한**, 채널을 오른쪽 클릭한 **이 채널 속도 제한**, 프로필의 **속도 제한**. 비워 두면 제한 없음,
  **0**이면 그 방향을 막습니다(올리기 0은 아무것도 내주지 않고, 받기 0은 첨부를 받지 않음). 사용자 설정 → 동기화의 전체 올리기·받기
  제한도 0을 받습니다. 그리고
  건 제한은 사용자 설정 → 동기화의 '크루·채널·사람별 속도 제한'에서 모아 보고 고치거나 지웁니다.

### 받은 첨부의 저장 공간

남에게서 받은 첨부는 **한도**(기본 2GiB) 안에서만 남고, 데이터 폴더가 있는 디스크에는 **최소 여유 공간**(기본 1GiB)을
늘 남깁니다. 넘으면 오래 보지 않은 첨부부터 원본을 비웁니다. 메시지와 썸네일은 그대로이고, 원본은 누르면 다른 기기에서
다시 받습니다(그 첨부를 가진 기기가 온라인이어야 함).

- 비우지 않는 것: 내가 올린 첨부, 이모지·크루 아이콘·프로필 이미지, 보관(고정)한 첨부, 받는 중이거나 방금 보거나 남에게
  내준 첨부.
- 앱: 사용자 설정 → **저장 공간**에서 사용량·한도·디스크 여유를 보고, 한도를 바꾸거나 받은 첨부를 모두 비우고, 보관한
  첨부를 풉니다. 첨부의 핀 단추로 보관합니다.

```bash
yangpa blob cache status                        # 받은 첨부·보관·늘 남기는 것의 크기, 한도, 디스크 여유
yangpa blob cache limit 10GB --min-free 2GB     # 한도 바꾸기(--reset이면 기본값으로)
yangpa blob cache clear                         # 받은 첨부의 원본을 지금 모두 비움(다시 받을 수 있음)
yangpa blob pin --crew "게임 모임" <블롭 ID>     # 보관(아직 없으면 받기 시작), blob unpin으로 풀기
yangpa blob pins
```

### 라이브러리: 주고받은 파일 한자리에서

왼쪽 레일의 **라이브러리**(책 모양)를 누르면 이 기기에서 보내거나 받은 첨부가 탐색기처럼 모입니다. 휘발성 채널의 첨부는
메모리에만 있어 나오지 않습니다.

> **후원자 전용**: 라이브러리와 콘텐츠 뷰어는 GitHub Sponsors나 Patreon의 **월 정기 후원자**가 씁니다. GitHub Sponsors에서 **3달러 이상 1회 후원**을 해도 결제한 날부터 30일 동안 쓸 수 있습니다. 후원한 뒤 사용자 설정 →
> **후원**(또는 잠긴 기능을 누르면 뜨는 창)에서 **GitHub로 확인**·**Patreon으로 확인**을 누르고, 브라우저에 뜬 승인 화면에서
> 허용하면 됩니다(GitHub는 앱이 보여 주는 코드를 넣음). 앱은 그 계정의 프로필과 후원 정보만 읽고, YANGPA 신원은 보내지
> 않습니다. 하루에 한 번 다시 확인하고(GitHub는 Tor로, Patreon은 Tor를 막아 직접 연결로), 구독이 끝나거나 1회 후원 뒤 30일이 지나면 다시 잠깁니다. 이 기능이 생기기 전부터 쓰던 기기는 30일 동안 그대로
> 씁니다. **내 기기 중 한 대에서만 확인하면** 결과가 내 다른 기기에도 전해져 그 기기들은 로그인하지 않아도 됩니다(Patreon은 한
> 계정을 기기 하나에만 연결할 수 있어, 여러 기기에서 로그인하면 먼저 연결한 기기가 끊깁니다).

- **폴더**: 왼쪽 나무에서 **전체 콘텐츠**를 누르면 모두, 크루 → 카테고리 → 채널을 누르면 그 안의 파일만 보입니다. 1대1 대화는
  상대 이름 폴더 하나입니다. 위쪽 경로를 눌러 바깥 폴더로 돌아가고, 찾기 칸은 지금 폴더에서 파일·크루·채널·사람 이름을 찾습니다.
- **보기**: 자세히(이름·크기·종류·올린 시간·받은 시간·공유한 사람·크루·채널·상태)와 갤러리(썸네일). 자세히 보기의 열 머리를
  누르면 그 열로 정렬합니다.
- **정렬·분류**: 위쪽 단추로 규칙을 여러 개 더하고 ↑↓로 우선순위를 바꿉니다. 정렬은 위 규칙부터 비교하고, 분류는 위 규칙으로
  먼저 나눈 뒤 그 안을 다음 규칙으로 다시 나눕니다(예: 크루 → 종류). 분류 머리말을 누르면 접힙니다. 보기와 규칙은 기억합니다.
- **고르기**: 누르면 하나, Ctrl·Shift를 함께 누르면 여러 개, Ctrl+A는 모두. 오른쪽 미리 보기 칸에서 원본 받기·저장·보관·
  재생과 메시지로 가기를 합니다.
- **콘텐츠 뷰어**: 파일을 두 번 누르거나 Enter, 메뉴·미리 보기 칸의 **뷰어로 보기**를 누르면 지금 보이는 차례대로 ↑↓로 넘겨
  봅니다(여러 개를 골랐으면 고른 것만). 라이브러리에서 연 뷰어에는 뷰어 설정의 종류·단어·순서 필터가 걸리지 않습니다.
- **관리**(오른쪽 클릭이나 미리 보기 칸, 여러 개를 골라도 됨): **공유 중단·재개**는 이 기기가 그 파일을 남에게 내줄지 정합니다(그
  파일을 실은 메시지 단위라 같은 메시지의 다른 첨부도 함께). **보관하기·보관 풀기**는 저장 공간 정리에서 그 파일을 뺍니다
  (이 기기에 없는 파일은 받아서 보관, 내가 이 기기에서 올린 파일은 늘 남아 해당 없음). **이 기기에서 지우기**(Delete 키)는 이
  기기의 원본만 지웁니다. 메시지와 썸네일은 남고, 가진 사람이 있으면 다시 받을 수 있습니다. 내가 올린 파일을 지우면 이 기기에서는
  더는 내주지 못합니다.
- 채팅에서도 메시지의 **⋯ 메뉴**에서 **공유 중단·재개**와 **첨부 보관하기·풀기**를 할 수 있습니다(라이브러리와
  같은 동작).
- 받지 않은 파일은 누를 때만 받습니다. 목록을 훑는 것만으로는 무엇을 보는지 다른 기기에 알려지지 않습니다.

### 첨부 다시 잇기

데몬은 첨부를 보낼 때 암호화한 사본을 따로 만들어 그것으로 내줍니다. 그래서 원본 파일을 옮기거나 지워도 공유는 멈추지
않습니다. 이 기기의 사본이 없어졌을 때(받은 첨부를 비웠거나 새 기기·다시 설치) 같은 파일이 있으면 일반 채널의 첨부에서
**파일 다시 잇기**로 그 파일을 고르세요. 파일을 첨부의 키로 다시 암호화해 해시가 정확히 같을 때만 받아들이고(한 바이트라도
다르면 거절), 받지 않고 바로 다 차며 보관(고정)되어 다시 내줍니다. 휘발성 채널의 첨부는 디스크에 두지 않아 다시 이을 수 없습니다.

### 보관 전용 노드

멤버가 모두 꺼져 있을 때를 대비해, 크루 관리자는 **키 없이 암호문만 보관하는 노드**를 지정할 수 있습니다. 보관 노드는
크루 멤버가 아니라 내용을 읽을 수 없고, 받아 둔 기록과 첨부를 **지금 멤버인 기기에게만** 내줍니다. 추방·밴된 사람이나
폐기된 기기는 받을 수 없습니다.

- 지정: 보관 노드 운영자가 만든 1회용 링크를 받아 크루 설정 → 시더 → 보관 전용 노드에서 지정합니다(크루 관리 권한).
  CLI는 `yangpa archive designate --crew "게임 모임" <링크>`입니다. 띄우는 법은 [headless.md](headless.md)를 보세요.
- 보관 범위: 공개 채널은 모두, 비공개 채널은 지정할 때 고른 것만. 휘발성 채널은 보관하지 않습니다.
- 내 시더 설정은 보관 노드에도 그대로 적용됩니다(시딩을 끄거나 뺀 채널은 내 기기에서 보관 노드로 가지 않음).
- 보관 노드가 아는 것: 멤버 목록(ID)과 들어온 시점, 누가 언제 어느 채널에 얼마만 한 메시지를 썼는지, 첨부 크기. 크루·채널
  이름, 메시지·파일 내용, 반응 같은 것은 알 수 없습니다.
- "시더 커버리지"에는 보관 노드가 따로 세어지고, 시더와 보관 노드가 둘 다 없을 때만 경고합니다.
- 해제하면(`yangpa archive revoke`) 보관 노드는 그 크루 데이터를 지우고 더 받지도 내주지도 않습니다.

## 8. Tor 연결과 P2P 전용 채널

앱의 모든 연결은 **Tor**를 거칩니다. 켜고 끄는 설정은 없습니다. 직접 연결은 관리자가 고른 **P2P 전용 채널** 안에서 경고를
보고 참가한 기기끼리, 내가 **신뢰 스위치**를 켠 사람·크루, 그리고 **내 기기끼리**만 씁니다(아래). 기기가 2대 이상이면 기기끼리
빠르게 잇기 위해 공개 STUN 서버에 내 주소를 묻습니다. 그 서버와 통신사는 내 실제 IP를 볼 수 있습니다. 오프라인 모드에서는 하지 않습니다.

```bash
yangpa net status        # mode(tor), onion_addr, bootstrap_progress
```

**하는 일:** 나가는 연결은 모두 Tor를 거치고, 들어오는 연결은 onion 서비스로 받습니다(NAT 뒤에서도 받을 수 있음). 네트워크
ID(PeerId)는 Tor 전용 키라 예전 빌드에서 쓰던 일반 모드 노드와 이어지지 않습니다.

**꺼져 있는 것:** 주소 광고(identify), DHT에 IP 등록, 같은 네트워크 탐색(mDNS), AutoNAT, 홀펀칭, 릴레이, 링크 미리보기
직접 조회(Tor를 거쳐서만 조회하고, 그럴 수 없으면 만들지 않음), 참가한 P2P 전용 채널 밖의 WebRTC 통화·화면공유(9장, 그 밖의 통화는 Tor로 소리만).

**대가와 한계:**

- 느립니다. 메시지 지연 목표는 3초(p95)이고, 파일은 동시 전송 수를 줄이고 한 번에 하나씩 받아 텍스트를 먼저 받습니다(7장
  표). 실제 속도는 Tor 회로가 정합니다. P2P 전용 채널과 서로 신뢰한 사람의 파일은 직접 연결이라 이 한도를 쓰지 않습니다.
  처음 켤 때 Tor 망 정보를 받느라 시간이 걸립니다(이후에는 캐시).
- **Tor 파일 회로**(설정 → 네트워크·Tor, `net.set_file_circuits`): 큰 첨부(조각 5개 이상, 보통 1MiB 넘게)를 Tor로 받을 때 상대마다 파일 전용
  회로를 0~4개 더 열어 나눠 받습니다. 기본은 0(끔)이고, 상대도 1 이상이어야 쓰입니다. 늘리면 빨라질 수 있지만 상대가 받아 갈
  때마다 이 기기의 onion 서비스가 회로를 더 자주 만들어 가드 찾기 공격에 조금 더 드러나므로, 0에서 올릴 때 경고를 확인받습니다.
- **통화:** WebRTC는 UDP라 Tor로 보낼 수 없습니다. 그래서 일반 통화 채널은 "Tor 통화"로 소리만 Tor로 나르고(말이 0.5~1.5초쯤
  늦게 닿음, 화면공유는 경고를 확인한 뒤 비상용 저화질로만), 제대로 된 화면공유와 빠른 통화는 참가한 P2P 전용 통화 채널이나
  서로 신뢰한 사람(신뢰 스위치)과 합니다(9장).
- Tor를 준비할 수 없으면 데몬이 시작하지 않습니다. **조용히 직접 연결로 넘어가지 않습니다.**
- 친구·멤버는 암호화 채널 안에서 내 신원을 압니다. Tor는 네트워크 관찰자에게서 IP를 숨길 뿐 친구에게서 나를 숨기지
  않습니다. 망 전체를 보는 관찰자의 시간 상관 분석 같은 Tor 자체의 한계는 그대로입니다.
- 직접 연결로 띄운 헤드리스 시더는 내 onion 주소로 걸지 못하고, 앱에는 그런 노드의 주소를 등록하는 설정(상시 노드)이
  없습니다. 크루에 시더를 붙이려면 시더를 Tor로 띄웁니다([headless.md](headless.md) "멤버가 닿게 하기").
- 막 만든 연락처 링크는 Tor 주소가 게시되기까지 잠시 닿지 않을 수 있습니다(3장).
- 앱은 IP 주소를 보여 주지 않습니다(설정 → 네트워크·Tor에는 onion 주소와 Tor 상태만).

### P2P 전용 채널

빠른 파일 전송이나 직접 통화가 필요한 채널은 크루 관리자가 **P2P 전용**으로 정할 수 있습니다. 그 채널의 메시지·파일·통화는
Tor를 거치지 않고, 참가한 기기끼리 직접 오갑니다. 채널 이름 앞에 P2P 표시가 붙습니다.

- **누가 정하나.** 그 채널을 관리할 수 있는 사람이 텍스트·통화 채널을 만들 때나 채널 설정에서 켭니다(포럼·분류, 내 기기끼리
  쓰는 공간은 안 됨). 언제든 다시 Tor로 되돌릴 수 있고, 되돌리면 P2P로만 오가던 지난 기록도 Tor로 모든 멤버와 맞춥니다.
- **참가해야 열립니다.** P2P 전용 채널에 들어가면 "이 채널의 참가자는 내 IP 주소를 볼 수 있습니다" 경고가 나오고, **참가**를
  눌러야 그 기기에서 채널이 열립니다. 참가하지 않으면 내용·입력창·통화 대신 경고만 보이고, 내 IP도 나가지 않습니다. 채널을
  만든 사람도 따로 참가해야 합니다.
- **기기마다 따로.** 참가는 그 기기에만 적용됩니다. 다른 기기에서 쓰려면 그 기기에서 다시 참가합니다. AI(자동화 토큰)는
  대신 참가할 수 없습니다.
- **무엇이 보이나.** 함께 참가한 기기끼리 서로의 IP 주소(대략의 위치·인터넷 회사)를 봅니다. 공유기 밖 주소를 알아낼 때 묻는
  STUN 서버의 운영자도 IP를 봅니다(내용은 종단간 암호화라 볼 수 없음). 공개 중계 노드는 쓰지 않습니다. 참가하지 않은
  멤버에게는 IP를 주지 않고, 채널 이름·설정·멤버 목록은 그대로 Tor로 오갑니다.
- **STUN 서버.** 설정 → 네트워크·Tor → STUN 서버에서 목록을 고치거나 기본 목록(Google·Cloudflare 공개 STUN)으로 되돌립니다.
  P2P 연결이 공유기 밖 주소를 알아낼 때만 쓰고 Tor 연결에는 쓰지 않습니다. 비우면 NAT 뒤의 기기끼리는 직접 연결이 덜 이어질 수
  있습니다.

  ```bash
  yangpa net stun                                    # 지금 목록(기본 목록인지)
  yangpa net stun set stun.example.org:3478 stun:198.51.100.7   # 바꾸기(포트를 빼면 3478, 8개까지)
  yangpa net stun reset                              # 기본 목록으로
  yangpa net stun off                                # STUN 쓰지 않기
  ```

- **크루 STUN 서버.** 크루 관리(`manage_space`) 권한이 있으면 크루 설정 → 개요에서 크루의 STUN 서버를 정할 수 있습니다(8개까지).
  멤버는 역할 권한 '크루 STUN 사용'이 있고 크루 설정에서 '이 크루의 STUN 서버 쓰기'를 켜야 씁니다. 켜면 내 STUN 목록 뒤에 붙여
  쓰고(직접 연결은 합친 목록의 앞 3개에만 물음), 통화에서는 그 크루의 통화에만 씁니다. 그 서버의 운영자도 내 IP를 봅니다.

- **그만두기.** 채널 위쪽의 "P2P 참여 그만두기"를 누르면 다시 잠깁니다. 이미 다른 참가자에게 보인 IP는 다시 숨길 수 없습니다.
  채널이 Tor로 돌아가거나 내가 크루를 나가면 참가도 풀리고, 다시 P2P 전용이 되면 경고부터 다시 봅니다.
- **통화.** P2P 전용 통화 채널은 참가한 기기만 통화하고, 직접 연결로 통화합니다.
- 휘발성 채널도 P2P 전용으로 둘 수 있습니다(내용은 여전히 RAM에만). 보관 전용 노드는 P2P 전용 채널을 보관하지 않습니다.
- 정하기·참가는 지금 앱에서만 합니다(CLI 명령은 없음).

### 신뢰 스위치

채널과 상관없이 특정 사람이나 크루와 빠르게 주고받고 싶으면 **신뢰 스위치**를 켭니다. 신뢰한다는 것은 **그 상대에게 이 기기의
IP 주소를 보여도 된다**는 뜻입니다.

- **어디서 켜나.** 사람은 상대 프로필에서, 크루는 크루 설정 → 개요의 "이 크루 신뢰"에서 켭니다. 사람이나 크루를 오른쪽
  클릭한 메뉴에서도 바로 켜고 끌 수 있습니다. 크루 신뢰는 그 크루의 멤버에게만
  적용됩니다. 켤 때마다 IP 노출 경고가 나오고, "다시 보지 않기"를 고르면 다음부터 생략합니다(설정 → 네트워크·Tor에서 경고를 다시
  켤 수 있음). 기본은 모두 꺼짐입니다.
- **어떻게 이어지나.** 기기 쌍마다 정해집니다.

  | 나 | 상대 | 연결 | 누구의 IP가 보이나 |
  | --- | --- | --- | --- |
  | 신뢰 | 신뢰 | P2P 직접 연결(P2P 전용 채널이 아니어도 모든 내용) | 서로 |
  | 신뢰 | 안 함 | 단방향: 상대가 Tor 출구를 거쳐 이 기기로 바로 연결 | 내 IP만(상대는 숨음) |
  | 안 함 | 신뢰 | 단방향: 이 기기가 Tor 출구를 거쳐 상대에게 바로 연결 | 상대 IP만(나는 숨음) |
  | 안 함 | 안 함 | Tor(onion끼리) | 아무도 |

  사람 신뢰든 함께 있는 크루의 신뢰든, 어느 쪽에서 왔든 서로 신뢰하면 P2P입니다. 예를 들어 B와 C가 둘 다 크루1을 신뢰하면 B·C는
  P2P로, 크루1을 신뢰하지 않는 A와는 단방향으로 이어집니다.
- **무엇이 보이나.** 상대 프로필에는 지금 연결 방식만 보이고, 앱은 누구의 IP 주소도 보여 주지 않습니다. 다만 상대가 다른 도구를
  쓰면 알아낼 수 있습니다. 공유기 밖 주소를 알아낼 때 묻는 STUN 서버(위 "STUN 서버")도 IP를 봅니다.
- **기기마다 따로.** 스위치는 그 기기에만 적용됩니다. 크루를 나가면 그 크루 신뢰가, 친구·연락처를 지우면 그 사람 신뢰가 꺼집니다.
  끌 수는 언제든 있지만 이미 보인 IP는 다시 숨길 수 없습니다.
- **이어지지 않을 때.** 신뢰한 쪽이 밖에서 연결을 받을 수 없거나(공유기가 포트를 열어 주지 않음), 양쪽 모두 직접 연결이 어려운
  공유기 뒤에 있으면 단방향·P2P가 이어지지 않고 Tor로 남습니다. 메시지는 그대로 Tor로 오갑니다.
- **통화.** 서로 신뢰한 사람과는 일반 통화 채널(Tor 통화)에서도 WebRTC로 바로 이어져 늦지 않고 화면공유도 제 화질입니다(9장). 이때
  상대와 STUN 서버에 IP가 보입니다. 한쪽만 신뢰한 사람, 익명 채널은 그대로 Tor로 나릅니다.
- AI(자동화 토큰)는 대신 켤 수 없습니다. CLI:

  ```bash
  yangpa trust get 세영          # 신뢰 스위치와 지금 연결 방식(친구·연락처 이름이나 사용자 ID, IP는 보이지 않음)
  yangpa trust user 세영         # 사람 신뢰 켜기(--off로 끄기)
  yangpa trust crew 크루1        # 크루 신뢰 켜기(--off로 끄기)
  ```

## 9. 음성·화면공유

- 통화 채널에서 통화하고 화면을 공유합니다. 프레임마다 종단간 암호화하며, 키는 참가자가 바뀔 때마다 새로 만들어
  참가자에게만 나눕니다(나간 사람은 이후 통화를 풀 수 없음).
- 상대가 화면을 공유하면 누르지 않아도 바로 보입니다('그만 보기'를 누르면 그 공유가 끝날 때까지 다시 켜지지 않음). 화면은 보는
  사람에게만 보냅니다. Tor로 오는 비상용 화면공유는 Tor 대역을 쓰므로 '화면 보기'를 눌러야 받습니다.
- 보는 화면 오른쪽 아래에 화면 소리 크기(이 통화 동안만, 스피커 음량에 곱해짐), 그만 보기, **PiP**(작은 창으로 보기), 전체화면
  버튼이 있습니다. 화면을 보다가 다른 채널로 가거나 창을 최소화하면(윈도) 저절로 PiP로 바뀌고, 통화 화면으로 돌아오면 닫힙니다.
  PiP 창은 앱 창의 캡처 차단을 받지 않으므로 휘발성 통화 채널에서는 PiP를 쓸 수 없습니다.
- **세부 설정.** 사용자 설정 → **음성·화면공유**에서 내가 보내는 화면·음성을 정합니다(이 기기만, 통화 중에 바꿔도 바로 적용).
  - 장치: 마이크·스피커 장치(기본은 시스템 기본 장치), 마이크 음량(0~200%), 스피커 음량(받는 소리 전체, 0~100%), 마이크
    테스트(입력 크기 막대, 고른 스피커로 내 목소리 듣기). 고른 장치를 빼 두면 시스템 기본 장치로 통화하고 한 번 알립니다.
  - 화면공유: 비디오 코덱(VP8·VP9), 출력 해상도(원본·2160p~480p 이하), 최대 프레임(자동·15·30·60), 최대 비트레이트(Kbps),
    대역이 모자랄 때 무엇을 먼저 줄일지(균형·프레임 유지·해상도 유지), 화면 소리 보내기와 그 음량(0~200%).
  - 음성(Opus): 최대 비트레이트, 패킷 길이(10~60ms), 스테레오, 오류 보정(FEC), 무음 때 전송 줄이기(DTX), 에코 제거·잡음 억제·
    자동 음량(에코 제거·잡음 억제는 기본 꺼짐, 자동 음량은 기본 켬). 스테레오·FEC·DTX·패킷 길이는 다음 연결부터 적용됩니다.
  - 음성 코덱: Opus(기본), **Mimi**(Kyutai, 약 1.1Kbps, 말소리용, 지연 약 0.2초), **DAC**(Descript, 약 24Kbps 고음질, 지연 약
    0.5초, CPU를 많이 씀). 신경망 코덱은 7명 이하 통화에서 같은 코덱 모델을 가진 상대에게만 쓰고, 나머지 상대에게는 Opus로
    보냅니다. 통화 화면 위에 'Mimi · N명'처럼 지금 신경망 코덱으로 보내는 상대 수가 나옵니다.
  - 신경망 코덱 모델은 실행 파일 안이 아니라 `yangpa-desktop.exe` 옆 `models` 폴더에 있습니다. 설치본(NSIS·MSI)과 포터블
    zip 모두 이 폴더가 함께 들어 있어 따로 받을 것이 없습니다. 빠졌거나 배포본과 다른(바뀌었거나
    손상된) 파일이 있으면 설정에 보이며 그 코덱 대신 Opus로 보냅니다.
  - 화면 인코더: **웹뷰 기본**(WebRTC, VP8·VP9)과 **ffmpeg 인코더** 다섯 가지 — AOM AV1(소프트웨어), SVT-AV1(소프트웨어),
    NVIDIA NVENC AV1(RTX 40 이상)·H.264·HEVC. 웹뷰 기본 인코더는 종단간 암호화 때문에 VP8·VP9만 되고 인코더 내부 값을 고를 수
    없습니다.
  - ffmpeg 인코더(데스크톱 앱, 윈도)를 고르면 화면공유를 누를 때 공유할 **모니터나 창**을 웹뷰 기본 선택 창과 같은 모양(창·전체 화면 탭,
    미리보기, 창 아이콘)의 앱 목록에서 고릅니다. 앱이 잡을 수 있는 화면만 나옵니다. OBS처럼
    비트레이트 방식(CBR·VBR·화질 고정 CQ/CRF), 목표·최대 비트레이트, 키 프레임 간격, 마우스 커서, NVENC 프리셋(P1~P7)·튜닝
    (고화질·저지연·초저지연)·멀티패스·Look-ahead·공간 AQ·H.264 프로파일, AOM 속도·화면 콘텐츠 도구, SVT-AV1 프리셋을 고릅니다
    (SVT-AV1은 저지연 모드라 VBR이 없습니다).
    공유 중에 바꾸면 인코더를 다시 띄워 잠깐 멈춘 뒤 적용됩니다. 지연을 늘리는 B-프레임은 쓰지 않습니다.
  - ffmpeg 인코더 화면은 7명 이하 통화에서 그 코덱을 풀 수 있는 시청자에게 보냅니다. 풀지 못하는 시청자(예: HEVC 하드웨어
    디코더가 없는 PC)에는 그 화면을 '대체 코덱'(VP8·VP9)으로 다시 인코딩해 보냅니다. 7명 이상 통화(SFU)에서 공유를 시작하면
    웹뷰 인코더로 공유합니다. 늦게 '보기'를 누른
    시청자는 다음 키 프레임(기본 2초 안)부터 봅니다.
  - ffmpeg는 `yangpa-desktop.exe` 옆 `ffmpeg` 폴더에 있습니다(설치본·포터블 모두 들어 있음, 화면공유에 쓰는 것만 넣은 LGPL 빌드, 약 21MB). NVENC는 NVIDIA 드라이버 531.61 이상에서 됩니다. 이 기기에서
    쓸 수 없는 인코더(NVIDIA GPU 없음 등)는 설정에서 고를 수 없게 보이고, 폴더가 없거나 바뀌었으면 웹뷰 인코더로 공유합니다.
- **두 가지 통화:** WebRTC 연결 후보에는 실제 IP가 들어 있어 통화 상대에게 보이고, Tor는 UDP를 나르지 못합니다. 그래서
  - **Tor 통화**(일반 통화 채널): WebRTC를 아예 쓰지 않고, 앱이 암호화한 소리 패킷을 데몬이 Tor 연결로 참가자에게 나릅니다. IP가
    드러나지 않는 대신 말이 0.5~1.5초쯤 늦게 닿습니다. 화면공유는 비상용입니다: 누르면 경고가 나오고, 확인하면 낮은 화질(가로 최대
    1280px)·초당 2프레임으로 '화면 보기'를 누른 사람에게만 갑니다(몇 초 늦고, 그동안 소리·메시지가 느려질 수 있음). 코덱은 설정에서 고른 것을 모두가 풀 수 있으면 그것
    (Mimi는 약 1.1kbps라 Tor에 잘 맞음), 아니면 Opus입니다. 같은 사람과 큰 첨부를 주고받는 동안에는 소리가 더 늦을 수 있습니다.
    스피커로 들으면 내 소리가 상대에게 울릴 수 있어 이어폰을 권합니다. 서로 신뢰한 사람(8장 "신뢰 스위치")과는 이 통화에서도
    WebRTC로 바로 이어(서로 IP가 보임) 지연이 짧고 화면공유도 제 화질이며, 상태 줄에 'Tor 통화 · N명과 직접 연결'로 보입니다.
    다른 사람과는 그대로 Tor입니다. 직접 잇는 사람만 있으면 화면공유 때 비상용 경고가 나오지 않습니다.
  - **P2P 전용 통화 채널**(참가한 경우, 8장): 직접 연결 WebRTC라 지연이 짧고 화면공유도 되지만 함께 참가한 사람에게 IP가 보입니다.
- 큰 통화를 나눠 보내는 SFU 호스트는 Tor로 도는 앱 기기가 맡지 않고, 직접 연결로 띄운 시더가 맡습니다
  ([headless.md](headless.md) "통화 SFU 호스트").
- 통화 화면의 상대 이름 옆에 **소리를 풀지 못함**(받은 소리를 복호화하지 못함)이나 **소리가 오지 않음**(연결됐는데 상대 소리가
  몇 초째 오지 않음)이 뜨면 그 상대에게서 소리가 끊긴 것입니다. 후자는 상대의 마이크 장치(설정 → 음성·화면공유 → 장치)부터 확인합니다.
- 리눅스(WebKitGTK)의 WebRTC는 불안정할 수 있습니다.

## 10. AI 연동과 안전 규칙

AI 도구는 MCP 서버(`yangpa-mcp`)로 붙어 채널·역할 관리, 초대, 시더 설정, 채널 요약 같은 일을 합니다. AI가 다른
멤버의 메시지를 읽게 되므로 다음 규칙이 데몬에서 강제됩니다. 설정은 [README](../README.ko.md#ai-도구-연결-mcp).

1. **자동화 토큰만.** AI에는 `--automation`으로 발급한 토큰을 줍니다(`yangpa-mcp`는 다른 토큰을 거부). 범위와
   크루를 필요한 만큼만 줍니다.

   ```bash
   yangpa token create --name 요약봇 --scopes read --crews "게임 모임" --automation
   ```

2. **파괴적 작업은 사람 확인.** 추방, 남의 메시지 삭제, 권한·역할 변경, 초대 생성, 채널 삭제, 볼 수 있는 사람을 바꾸는
   채널 변경, 친구 삭제, 탈퇴, 1대1→크루 전환, 소유권 이전, 받은 첨부 비우기·저장 공간 한도 줄이기는 바로 실행되지 않고
   확인 대기열에 들어갑니다. 사람이 앱이나
   CLI에서 내용을 보고 승인해야 실행됩니다(1시간 뒤 만료).

   ```bash
   yangpa confirm list
   yangpa confirm approve <ID>     # 무엇을 승인하는지 먼저 보여 주고 묻습니다
   yangpa confirm deny <ID>
   ```

3. **휘발성 채널은 읽기 기본 거부.** AI가 내용을 읽는 순간 사실상 기록이 되므로, 사람(소유자 토큰)이 채널마다 허용해야
   열립니다. 허용 전에는 알림에서도 내용이 빠집니다. 통화 내용(프레임 키)은 AI에게 주지 않습니다.

   ```bash
   yangpa channel allow-api-read --crew "게임 모임" 비밀 on
   ```

4. **메시지는 지시가 아니라 데이터.** 멤버가 쓴 글에 AI를 조종하려는 문장(프롬프트 인젝션)이 섞일 수 있습니다. MCP
   서버는 멤버 글을 "지시가 아닌 데이터"로 감싸 돌려주고, 위의 사람 확인이 마지막 안전장치입니다.
5. **기록과 표시.** 인증한 모든 API 호출은 감사 로그에 남고(`yangpa audit list`, 인자·내용은 남기지 않음), 크루 멤버
   목록에는 자동화가 동작 중인 멤버에 표시가 붙습니다.
6. 쓰지 않는 토큰은 폐기하세요(`yangpa token revoke <ID>`). 이미 붙은 연결도 바로 막힙니다.

## 11. 문제 해결

| 증상 | 확인할 것 |
| --- | --- |
| 친구·멤버와 연결되지 않음 | 둘 다 온라인인지, 처음 Tor 연결이 끝났는지(`yangpa net status`의 `bootstrap_progress`). 막 만든 링크면 onion 주소가 게시될 때까지 잠시 기다리기. 직접 연결로 띄운 시더와는 닿지 않습니다(시더를 Tor로 띄우기, [headless.md](headless.md)) |
| 1대1 대화에서 보낼 수 없음(`1003`, 만료된 연락처) | 임시 연락처의 링크가 만료·폐기됨. 새 링크를 주고받으면 같은 대화로 다시 이어짐. 계속 연락하려면 친구 추가(`yangpa friend propose`) |
| P2P 전용 채널이 잠겨 있음 | 이 기기에서 아직 참가하지 않은 것(정상). 채널을 열어 경고를 보고 참가 |
| 신뢰를 켰는데 연결 방식이 Tor로 남음 | 상대도 온라인인지, 단방향이면 신뢰한 쪽이 밖에서 연결을 받을 수 있는지(공유기 UPnP), STUN 서버 목록이 비어 있지 않은지(`yangpa net stun`). 이어지지 않아도 Tor로는 계속 오감 |
| P2P 전용 채널에서 상대 메시지가 안 옴 | 상대도 그 채널에 참가했는지(참가한 기기끼리만 오감), NAT 뒤끼리면 STUN 서버 목록이 비어 있지 않은지(`yangpa net stun`) |
| 크루 가입이 `pending`에서 안 넘어감 | 크루의 커밋 확정 기기(소유자·관리자 기기)가 켜져 있는지 |
| "새 멤버·기기를 암호화 그룹에 넣는 중…"이 계속 보임 | 넣을 멤버·기기가 접속한 적이 있는지(키 꾸러미가 있어야 넣음). 그 기기를 크루에서 빼거나 폐기해도 사라짐 |
| 예전 기록이 안 보임 | 그 채널의 과거 기록 공개가 꺼져 있으면 정상. 켜져 있으면 `yangpa seed coverage`로 제공하는 시더가 있는지 |
| 첨부가 안 받아짐 | 피어 설정의 종류·자동 내려받기 한도, `yangpa blob cache status`의 한도·디스크 여유(자리가 없으면 자동으로 받지 않음), 수동으로 `yangpa blob fetch` |
| 예전 첨부가 다시 받아야 하는 상태임 | 저장 공간 한도로 원본을 비운 것(정상). 남길 첨부는 보관(`yangpa blob pin`)하거나 한도를 올리기 |
| `1006` 사람 확인 대기 | AI(자동화 토큰)가 요청한 파괴적 작업. `yangpa confirm list` |
| `1007` | 휘발성 채널의 AI 읽기가 허용되지 않음(정상) |
| 데몬이 시작하지 않음(Tor 오류) | 데이터 경로의 `arti/` 권한, 로그의 Tor 오류. 시작은 했는데 `bootstrap_progress`가 오르지 않으면 바깥으로 나가는 TCP가 막혔는지. 직접 연결로는 넘어가지 않습니다 |
